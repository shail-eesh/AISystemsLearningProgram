### T4 · Transformer from scratch

A decoder-only GPT in PyTorch: single-head function, looped multi-head oracle,
batched module, four position schemes, LayerNorm/RMSNorm, pre/post-norm switch,
weight tying, four samplers, a naive KV cache, and an induction-head probe.
Seven-step ladder, **121 tests**.

| check | result |
|---|---|
| logit parity vs an independently written reference (`F.scaled_dot_product_attention`, 3 separate q/k/v Linears, `torch.nn.LayerNorm`) | max relative diff **3.8e-07**, loss diff **0.0** |
| loss curve vs that reference, 3 seeds each, matched init | gap **0.0400** against a seed-noise band of **0.2304** — **0.17×** |
| generated tape lines matching the grammar exactly | **100%**, all distinct |
| …of which have a coherent high and low | **36%** |
| induction head, best head, variable-period task | **0.347** = **9.1× chance** |
| 2-layer vs 1-layer repeat accuracy | **94.0%** vs 64.9% (**+29.1 pts**) |
| KV cache | token-identical, **3.19×** at 180 tokens |
| position bake-off | RoPE **1.0224** < learned 1.1065 < none 1.1156 < sinusoidal 1.1178 |

**Four bugs found by the tests, all of them silent failures:**

1. `apply_rope` with a *negative* offset sliced from the end of the angle table
   (Python indexing) and returned a wrong rotation with no error. Found by
   parameterising the relative-phase test over `m < n`. Now raises.
2. `apply_rope` called `.float()` for stability, which *downcast* float64 — so
   the float64 identity test could never do better than 1e-7. Now promotes to at
   least float32 and never demotes; the identity measures **1.8e-15**.
3. The sinusoidal table (entries in ±1) drowned 0.02-std token embeddings by
   ~50×; initial loss came out *above* ln(V) because the logits were nearly pure
   position. Scaled to the embedding init, and documented.
4. **The induction probe measured a positional shortcut.** With a fixed repeat
   period, "attend 24 slots back" solves the task, and a *one-layer* model scored
   30× chance with 100% accuracy — which should be impossible. Rebuilt on
   variable per-row periods (10–14) and calibrated in both directions: a planted
   head scores 1.000, a fixed-offset head scores 0.128.

Two results worth keeping that contradict the folklore:

- **Post-norm beat pre-norm** at 6 layers / lr 3e-3 (1.78 vs 2.79), and stalled
  at 3.30 in the other three cells of the 2×2. Pre-norm is robustness, not
  quality.
- **The one-layer induction model has the *better* attention score (0.438 vs
  0.347) and much worse behaviour.** It hedges across the five candidate offsets.
  An attention map that looks right is not a circuit that works.

### T15 · AlphaSLM

Corpus → FinTok → packed uint16 shards → a restartable harness → a three-rung
scaling study → per-register evaluation, plus the GPU runner. Five-step ladder,
**68 tests**.

| check | result |
|---|---|
| shard rebuild vs committed checksums | identical, both splits |
| documents in both splits | **0** (split by document, before packing) |
| characters per FinTok token | **4.82** |
| resume: 160 straight vs 80 + checkpoint + 80 | max parameter diff **0.0** |
| accumulation: 16×1 vs 4×4 | max parameter diff **6.3e-06** (float32 reassociation, not a bug) |
| scaling ordering, 0.6M → 1.8M → 5.9M | 0.8129 → 0.8017 → **0.7955**, holds |
| power law fitted on the end rungs, checked on the middle | predicted 0.8043 vs actual 0.8017, **+0.33%** |
| held-out filing perplexity | 2.2986 → 2.2862 → **2.2667** (**1.014×**) |
| register/issuer checks on generated text | **83%** |

**The finding.** 10.7× the parameters bought 0.017 nats, which looks broken next
to a published scaling chart. Splitting the per-token loss by token class
explains it completely: numeric tokens are **19.5%** of the corpus at **3.563
nats** (near-uniform — the generator draws prices from continuous ranges), and
prose tokens cost **0.086 nats** (near-deterministic — templates), a floor the
*smallest* rung already reaches. About 90% of the remaining loss is dice rolls.
The margin is small *by construction*; the fix is a harder corpus (T23, T38), not
a bigger model. Chinchilla says the same thing from the other direction: the
three rungs see 22%, 6.9% and 2.1% of their compute-optimal token budgets.

Also measured, and it changed the evaluation code: five random-window draws on
one model gave a spread of **0.082 nats** — five times the entire margin between
the smallest and largest model. Sequential non-overlapping windows gave the same
number five times out of five. `Trainer.evaluate` walks the split.

### GPU lane

`gpu-runner/t15_alphaslm_40m.py` (plus a `gpu-runner/README.md` stating the
contract every runner follows). It imports T15's own harness — same loop, same
checkpoints, same shards — prints a plan and refuses to start if it does not fit:

```
parameters          39,550,976      estimated VRAM  7.89 GB (fits 12 GB)
context                    512      corpus     2,371,748 tokens = 207.2 epochs
batch x micro           24 x 2      Chinchilla        62.1% of budget
```

It also prints the 207-epoch warning, because that is the number that decides
whether the run is worth the electricity. Recommendation in the README and in
episode 4: run it anyway, to watch held-out perplexity flatten while training
loss keeps falling.
